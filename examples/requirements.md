# BRD/FRD — фрагмент

> Обезличенный пример требований к процессу «договор хранения + операции с драгоценными металлами».
> Связанные артефакты: [схемы](../README.md#схемы), [OpenAPI](api.yaml), [UAT](uat.md).

## 1. Контекст

Банк открывает клиентам договор хранения ценностей и счёт, принимает и выдаёт металл, начисляет комиссию, формирует выписку и закрывает договор.

В процессе участвуют фронт-офис, АБС, касса и процессинг. Часть операций выполняется асинхронно, поэтому критичны статусы, повторные запросы и сверка остатков.

## 2. Цели

| ID | Цель | Метрика |
|---|---|---|
| G-01 | Сократить время обслуживания | Открытие договора и счёта — до 15 минут |
| G-02 | Убрать ручные сверки на happy path | ≥ 95% операций без ручного разбора |
| G-03 | Сделать ошибки понятными | 100% ошибок с кодом, сообщением и действием |
| G-04 | Сократить дефекты на UAT | −25% дефектов категории A/B |

## 3. Scope

**Входит:** открытие, активация, приостановка и закрытие договора; счёт; внесение и выдача металла; комиссии; выписки; интеграции четырёх систем; сверка остатков; UAT.

**Не входит:** кредитные и депозитные продукты, биржевые котировки, бухгалтерская отчётность банка, мобильное приложение клиента.

## 4. Функциональные требования

| ID | Требование | Приоритет | Критерий приёмки |
|---|---|---|---|
| FR-01 | Создать договор в статусе `DRAFT` | Must | Возвращаются `contractId`, статус и дата создания |
| FR-02 | Активировать договор после открытия счёта | Must | Переход `OPEN → ACTIVE`; при ошибке статус не меняется |
| FR-03 | Открыть счёт по договору | Must | Возвращаются `accountId`, маска номера, валюта, статус `OPEN` |
| FR-04 | Создать операцию внесения металла | Must | `operationId`, статус `PENDING`, идемпотентность по ключу |
| FR-05 | Создать операцию выдачи | Must | Проверка остатка; при недостатке — `409 INSUFFICIENT_BALANCE` |
| FR-06 | Вернуть статус операции | Must | `PENDING / CONFIRMED / REJECTED / CANCELLED` |
| FR-07 | Обработать повтор с тем же `Idempotency-Key` | Must | Тот же результат, дубль не создаётся |
| FR-08 | Закрыть договор | Must | Только при нулевом остатке, без арестов и активных ордеров |

## 5. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-01 | p95 синхронных операций — не более 1,5 с |
| NFR-02 | Доступность контура — 99,5% в месяц |
| NFR-03 | Все изменения договора и счёта — в журнале аудита |
| NFR-04 | Доступ по ролям; данные вне области видимости не раскрываются |

## 6. Бизнес-правила

- `RULE-01` — валюта счёта совпадает с валютой договора.
- `RULE-02` — вес металла больше нуля, точность — до 6 знаков.
- `RULE-03` — выдача запрещена при недостаточном остатке.
- `RULE-04` — при расхождении остатков создаётся инцидент и ручной разбор.
- `RULE-05` — закрытие запрещено при остатке, аресте или активном ордере.
