# UAT-план

> Обезличенный план приёмочного тестирования. Связанные артефакты: [сценарии](05-test-scenarios.md), [требования](02-requirements.md), [трассировка](06-traceability-matrix.md).

---

## 1. Цель

Подтвердить, что решение соответствует бизнес-требованиям, готово к промышленной эксплуатации и может быть передано в поддержку.

## 2. Scope

**Входит:**

- открытие, активация, приостановка и закрытие договора;
- открытие и закрытие счёта;
- внесение и выдача ценностей;
- комиссии и выписки;
- интеграционные сценарии: таймаут, retry, идемпотентность, расхождение;
- роли и доступы;
- ошибки и сообщения пользователю.

**Не входит:**

- нагрузочное тестирование (отдельный этап);
- тестирование безопасности (отдельный этап);
- миграция исторических данных (отдельный проект).

## 3. Роли

| Роль | Ответственность |
|---|---|
| Владелец продукта | Приоритеты, приёмка, sign-off |
| Системный аналитик | Сценарии, трассировка, разбор требований |
| Тестировщик | Подготовка данных, прогон, дефекты |
| Бизнес-пользователь | Проверка сценариев, обратная связь |
| Разработка | Исправления, логи, диагностика |
| Поддержка | Проверка runbook и инструкций |
| ИБ | Проверка доступов и ПДн |

## 4. Окружение

| Компонент | Версия / комментарий |
|---|---|
| Стенд | UAT, изолированный от прода |
| АБС | Тестовый контур |
| Касса | Тестовый контур |
| Процессинг | Mock / sandbox |
| Данные | Синтетические, без ПДн |
| Доступ | По ролям, согласован с ИБ |

## 5. Критерии входа

- [ ] Требования согласованы и заморожены.
- [ ] API-контракты опубликованы.
- [ ] Стенд доступен.
- [ ] Тестовые данные подготовлены.
- [ ] Роли и доступы настроены.
- [ ] Известные дефекты заведены в Jira.
- [ ] Команда ознакомлена со сценариями.

## 6. Критерии выхода

- [ ] Все P0-сценарии пройдены.
- [ ] Все P1-сценарии пройдены или имеют согласованный обход.
- [ ] Нет открытых Blocker/Critical.
- [ ] Дефекты Major имеют план исправления.
- [ ] Runbook и инструкции проверены поддержкой.
- [ ] Получен sign-off владельца продукта.
- [ ] Решение готово к релизу.

## 7. Расписание (пример)

| Этап | Длительность | Результат |
|---|---|---|
| Подготовка | 2 дня | Стенд, данные, доступы |
| Smoke | 1 день | Базовая работоспособность |
| Основной прогон | 5 дней | P0/P1 сценарии |
| Регресс | 2 дня | Повтор после исправлений |
| Демо и sign-off | 1 день | Приёмка |

## 8. Дефекты и приоритеты

| Severity | Определение | SLA |
|---|---|---|
| Blocker | Блокирует тестирование | Исправить в день обнаружения |
| Critical | Ломает ключевой сценарий | До релиза |
| Major | Есть обходной путь | До релиза или согласованный обход |
| Minor | Косметика | Следующий релиз |

## 9. Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Стенд нестабилен | Средняя | Высокое | Резервный контур, smoke заранее |
| Нет тестовых данных | Средняя | Высокое | Генератор данных, согласование с ИБ |
| Поздние изменения требований | Высокая | Среднее | Change request, impact analysis |
| Недоступен процессинг | Низкая | Высокое | Mock, sandbox |
| Не хватает бизнес-пользователей | Средняя | Среднее | Заблаговременное бронирование |
