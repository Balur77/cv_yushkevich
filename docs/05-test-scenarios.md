# UAT-сценарии

> Обезличенный набор проверок для процесса «договор хранения + операции с металлом».
> Связанные артефакты: [требования](02-requirements.md), [матрица трассировки](06-traceability-matrix.md), [OpenAPI](03-api-specification.yaml).

---

## 1. Подход

- **Позитивные сценарии** проверяют happy path.
- **Негативные** — отказы, ошибки, недостаточные права.
- **Граничные** — нулевые и максимальные значения, даты, округления.
- **Интеграционные** — таймауты, retry, идемпотентность, расхождения.
- **Регрессионные** — повторная проверка после исправлений.

Приоритеты:

| Приоритет | Значение |
|---|---|
| P0 | Блокирует релиз |
| P1 | Критично для бизнеса |
| P2 | Важно, есть обходной путь |
| P3 | Желательно |

## 2. Сценарии

| ID | Требование | Сценарий | Предпосылки | Шаги | Ожидаемый результат | Приоритет |
|---|---|---|---|---|---|---|
| UAT-01 | FR-01, FR-07 | Открытие договора и счёта | Клиент активен, документы валидны | 1. Создать договор. 2. Открыть счёт. 3. Проверить статус | Договор `OPEN`, счёт `OPEN`, маска номера, `contractId` и `accountId` возвращены | P0 |
| UAT-02 | FR-02 | Активация договора | Договор `OPEN`, счёт открыт | 1. Активировать договор. 2. Проверить статус | Договор `ACTIVE`, событие в аудите | P0 |
| UAT-03 | FR-11, FR-13 | Внесение металла: успех | Счёт активен, остаток 0 | 1. Создать операцию `DEPOSIT`. 2. Дождаться `CONFIRMED`. 3. Проверить остаток | Операция `CONFIRMED`, остаток увеличен, инцидента нет | P0 |
| UAT-04 | FR-12 | Выдача металла: успех | Достаточный остаток | 1. Создать `WITHDRAWAL`. 2. Подтвердить. 3. Проверить остаток | Операция `CONFIRMED`, остаток уменьшен | P0 |
| UAT-05 | FR-12, RULE-03 | Выдача больше остатка | Остаток меньше запрошенного | 1. Создать `WITHDRAWAL` на сумму больше остатка | `409 INSUFFICIENT_BALANCE`, остаток не изменён | P0 |
| UAT-06 | FR-14, RULE-09 | Повтор с тем же `Idempotency-Key` | Успешная операция уже создана | 1. Повторить тот же запрос с тем же ключом | Тот же `operationId`, дубль не создан, остаток не изменился | P0 |
| UAT-07 | FR-14 | Повтор с тем же ключом и другим payload | Операция уже создана | 1. Повторить запрос с тем же ключом, но другим весом | `409 IDEMPOTENCY_PAYLOAD_MISMATCH`, ручной разбор | P1 |
| UAT-08 | FR-15 | Таймаут процессинга | Процессинг отвечает дольше таймаута | 1. Создать операцию. 2. Смоделировать таймаут. 3. Проверить retry | Операция не дублируется, статус `PENDING` / `MANUAL_REVIEW`, есть запись в журнале | P0 |
| UAT-09 | FR-16 | Расхождение остатков | После операции остатки АБС и кассы разные | 1. Подтвердить операцию. 2. Запустить сверку | Создан инцидент, операция `MANUAL_REVIEW`, договор нельзя закрыть | P0 |
| UAT-10 | FR-05, RULE-06 | Закрытие при остатке > 0 | На счёте есть остаток | 1. Запросить закрытие | `409 CONTRACT_HAS_BALANCE`, статус не изменён | P0 |
| UAT-11 | FR-05, RULE-07 | Закрытие при активном ордере | Есть незавершённый ордер | 1. Запросить закрытие | `409 ACTIVE_ORDER_EXISTS`, статус не изменён | P0 |
| UAT-12 | FR-03, FR-04 | Блокировка и разблокировка счёта | Счёт активен | 1. Заблокировать. 2. Попробовать операцию. 3. Разблокировать | Операция запрещена в `BLOCKED`, после разблокировки доступна | P0 |
| UAT-13 | FR-17, RULE-05 | Начисление комиссии | Период корректен, договор активен | 1. Начислить комиссию. 2. Проверить сумму и округление | Комиссия `CHARGED`, сумма соответствует правилам | P1 |
| UAT-14 | FR-18 | Формирование выписки | Есть операции за период | 1. Запросить PDF. 2. Дождаться `READY`. 3. Скачать | Файл сформирован, период и операции корректны | P1 |
| UAT-15 | FR-20 | Доступ вне роли | Пользователь без права закрытия | 1. Попробовать закрыть договор | `403 FORBIDDEN`, действие в аудите | P0 |
| UAT-16 | FR-20 | Доступ к чужому договору | Пользователь другой области видимости | 1. Запросить договор по ID | `403 FORBIDDEN` или `404 NOT_FOUND` (без раскрытия) | P0 |
| UAT-17 | FR-22 | Невалидный металл | Справочник металлов загружен | 1. Создать операцию с `metalCode = XXX` | `422 UNKNOWN_METAL_CODE`, понятное сообщение | P1 |
| UAT-18 | FR-22, RULE-03 | Нулевой/отрицательный вес | Счёт активен | 1. Создать операцию с весом 0 / -1 | `422 INVALID_WEIGHT` | P1 |
| UAT-19 | NFR-02 | Время ответа | Нагрузка в пределах нормы | 1. Выполнить 100 запросов. 2. Замерить p95 | p95 ≤ 1,5 с для синхронных операций | P1 |
| UAT-20 | NFR-06 | Retry с backoff | Внешний сервис недоступен | 1. Смоделировать 503. 2. Проверить попытки | Не более 5 попыток, интервал растёт, дублей нет | P1 |
| UAT-21 | RULE-01 | Несовпадение валют | Договор в BYN | 1. Открыть счёт в USD | `422 CURRENCY_MISMATCH` | P1 |
| UAT-22 | RULE-11 | Точность суммы | Сумма с 3 знаками | 1. Передать `10.999`. 2. Проверить сохранение | Округление по правилам, в БД decimal(18,2) | P2 |

## 3. Тестовые данные

| Сущность | Пример | Назначение |
|---|---|---|
| Клиент | `clientId = 6f1c2a9e-...` | Позитивный сценарий |
| Договор | `externalNumber = ST-2026-000123` | Уникальность |
| Счёт | `accountNumberMask = **** 1234` | Маска |
| Металл | `XAU`, вес `12.500000` | Позитив |
| Металл | `XXX` | Негатив |
| Сумма | `0`, `-1`, `10.999` | Границы |
| Дата | `2026-10-29`, `2026-02-30` | Валидация дат |
| Ключ | `3f9c1a7e-...` | Идемпотентность |

## 4. Критерии входа и выхода

**Вход:**

- требования согласованы;
- API-контракты опубликованы;
- тестовый стенд доступен;
- тестовые данные подготовлены;
- роли и доступы настроены.

**Выход:**

- все P0 и P1 сценарии пройдены;
- дефектов P0 нет;
- дефекты P1 имеют согласованный обходной путь;
- результаты и доказательства приложены;
- получен sign-off бизнеса.

## 5. Дефекты

| Severity | Описание | Реакция |
|---|---|---|
| Blocker | Нельзя продолжить тестирование | Исправить немедленно |
| Critical | Ломает ключевой сценарий | Исправить до релиза |
| Major | Есть обходной путь | Исправить до релиза или согласовать |
| Minor | Косметика / удобство | В следующий релиз |

## 6. Артефакты прогона

- отчёт о результатах;
- список дефектов со ссылками на Jira;
- логи и `X-Request-ID` для интеграционных кейсов;
- скриншоты/видео для демо;
- подписанный sign-off.
